# ADS127L11 Configuration Analysis

Generated by reviewing the ADS127L11 datasheet against firmware `OpenSourceDiffVM-RevB.ino`.

---

## Register Configuration

| Register | Value | Set by firmware |
|----------|-------|-----------------|
| CONFIG1 | 0x00 (reset default) | No — left at default after RESET |
| CONFIG2 | 0x00 (reset default) | No — left at default after RESET |
| CONFIG3 | 0x18 = 0b00011000 | Yes — `initAdc()` |
| CONFIG4 | 0x80 = 0b10000000 | Yes — `initAdc()` |

**CONFIG3 breakdown:**
- `DELAY[2:0]` = 000 → 0 fMOD cycles conversion-start delay
- `FILTER[4:0]` = 11000b → **Sinc4 (OSR = 32) + Sinc1 (OSR = 100)**

**CONFIG4 breakdown:**
- Bit 7 `CLK_SEL` = 1 → **External clock** (25 MHz from Teensy)
- All other bits = 0 (defaults)

**CONFIG1 / CONFIG2 defaults (not explicitly written):**
- CONFIG1 = 0: 1× input range, no input precharge buffers, no VCM output, low reference range
- CONFIG2 = 0: High-speed mode (`SPEED_MODE` = 0, requires fMOD ≥ 12.5 MHz), data-output mode

> **Fragility note:** CONFIG1 and CONFIG2 are never explicitly written. Any spurious RESET would
> leave CONFIG4 at 0x00, switching to the internal oscillator. These registers should be written
> explicitly during `initAdc()` as a defensive measure.

## Filter Selection: Sinc4 + Sinc1, OSR = 3200

From Table 8-25 (CONFIG3 FILTER[4:0] field descriptions):

```
FILTER = 11000b (24) = Sinc4 (OSR = 32) + Sinc1 (OSR = 100)
Total decimation ratio = 32 × 100 = 3200
```

Signal path through the digital filter:
```
Modulator (fMOD = 12.5 MHz)
    → Sinc4 decimator (OSR = 32) → 390.625 kHz intermediate rate
    → Sinc1 decimator (OSR = 100) → 3906.25 SPS output
```

### Filter Characteristics at fMOD = 12.5 MHz

| Parameter | Value |
|-----------|-------|
| Output data rate | 12.5 MHz / 3200 = **3906.25 SPS** |
| Sinc4 intermediate rate | 390.625 kHz |
| −3 dB bandwidth | ≈ 0.443 × 390.625 kHz / 100 ≈ **1730 Hz** |
| Sample period | 256 µs |
| Group delay (approx) | sinc4: 31/fMOD ≈ 2.5 µs + sinc1: 99 × 2.56 µs ≈ **256 µs total** |

The Sinc4 stage provides sharp nulls at multiples of fMOD/32 = 390.625 kHz, strongly rejecting
clock-related interference. The Sinc1 stage does the bulk averaging down to the final output rate.

The −3 dB bandwidth of ~1730 Hz is **~4.5× above the firmware chop rate (~385 Hz)**, so the
chopped measurement signal passes through without filter-induced amplitude error.

## Clock Frequency Assessment

**fCLK = 25 MHz → fMOD = fCLK / 2 = 12.5 MHz**

High-speed mode requires fMOD ≥ 12.5 MHz (CONFIG2 `SPEED_MODE` = 0). The firmware operates
**exactly at the minimum boundary** for high-speed mode.

### Impact

The datasheet SNR/DR specifications for high-speed mode are tabulated at fMOD = 25.6 MHz (maximum).
Running at 12.5 MHz means the modulator oversamples the input at half the maximum rate, resulting in:

- ~3 dB higher quantization noise floor vs. operating at fMOD = 25.6 MHz
- Same output data rate (OSR = 3200 decimates away the extra samples regardless)
- Same −3 dB bandwidth

### Recommendation

The Teensy 4.x can output clock frequencies well above 25 MHz. Changing to
**fCLK = 51.2 MHz → fMOD = 25.6 MHz** (the datasheet maximum) would recover
approximately **3 dB of SNR** at no cost to data rate or bandwidth. This is the most
straightforward hardware improvement available.

## Effective Number of Bits (ENOB)

### ADC per-sample performance

From the ADS127L11 electrical characteristics (high-speed mode):

| Configuration | Dynamic Range | ENOB |
|---------------|---------------|------|
| Wideband filter, OSR = 64 (datasheet min) | 109 dB min / 111.8 dB typ | 17.9 bits typ |
| Sinc4 + Sinc1, OSR = 3200 (our config, estimated) | ~115–117 dB typ | ~18.9–19.2 bits |

The nominal 24-bit output word has roughly **5 LSBs of noise** at the 3906 SPS output rate.
ENOB ≈ **19 bits per output sample**.

### After averaging N chop cycles

Each doubling of averages adds 0.5 bits. The firmware accumulates statistics across
`integrationCycles` chop cycles:

| Averages (N) | Wall time | ENOB | Input-referred noise (RMS) | Limiting factor |
|--------------|-----------|------|----------------------------|-----------------|
| 1 | ~2.6 ms | ~19 bits | ~1.5 nV (ADC-dominated) | ADC noise |
| 100 | ~260 ms | ~22 bits | ~2.7 nV | AD8428 preamp |
| 1000 | ~2.6 s | ~24 bits | ~0.85 nV | AD8428 preamp |
| 10000 | ~26 s | ~24 bits | ~270 pV | AD8428 preamp |

At N ≈ 1000 cycles, the 24-bit word length ceases to be the bottleneck. Beyond this point,
resolution is limited by the **AD8428 input noise (1.5 nV/√Hz)**, which is the intended design.
The ADC is not the limiting factor — this is correct for a nanovolt-level instrument.

### Noise budget (1-second integration, ~390 chop cycles)

| Source | Contribution (input-referred RMS) |
|--------|------------------------------------|
| AD8428 × 4 preamp chain | ~1.5 nV/√Hz × √(~400 Hz BW) ≈ **30 nV** per single half-cycle |
| After √390 averaging | ≈ **1.5 nV RMS** |
| ADS127L11 ADC (at N=390) | < 0.1 nV (negligible vs. preamp) |
| Reference drift (compensated) | < 25 nV (uncompensated); < a few nV (with filter-error compensation) |

## Summary

| Item | Assessment |
|------|-----------|
| Filter selection (sinc4+sinc1, OSR=3200) | Correct and well-suited for chopped DC measurement |
| Output data rate (3906.25 SPS) | Correct — matches firmware constant `EST_FSPS` |
| −3 dB bandwidth (~1730 Hz) | Good — well above chop rate, no signal attenuation |
| fCLK = 25 MHz (fMOD = 12.5 MHz) | Valid but at the minimum — upgrade to 51.2 MHz for ~3 dB improvement |
| CONFIG4 CLK_SEL=1 (external clock) | Correct |
| CONFIG1/CONFIG2 not explicitly written | Works, but fragile — recommend explicit init |
| ENOB per output sample | ~19 bits at 3906 SPS |
| ENOB after ~1000-cycle averaging | ~24 bits (then preamp-noise limited, as intended) |
| System resolution at 1 s averaging | ~1.5 nV RMS input-referred — consistent with 8.5-digit meter goal |
